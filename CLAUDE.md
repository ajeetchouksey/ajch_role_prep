# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

`ajch_role_prep` holds **Role Prep**: interview practice for AI roles, its own app at
roleprep.aaryaai.dev. Every question has a separate bar for **Tech**, **Tech Lead**
and **Leadership** interviews. This repo owns three things:

1. **Content** in `content/roleprep/` (format `roleprep@2`).
2. **The app** in `app/`: pre-rendered public pages plus an installable PWA for
   practice, served with Role Prep's API (`/api/*`, `/mcp`) by one Cloudflare
   Worker. Content and app ship from the same commit. See
   `docs/06-app-architecture.md` and the `roleprep-engineering` skill.
3. **The agent kit** in `.claude/` that writes, reviews, builds, tests and
   releases Role Prep, also packaged as the `roleprep-kit` Claude Code plugin.

Sign-in uses the AaryaAI account at api.aaryaai.dev (ajch_platform);
aaryaai.dev/roleprep redirects to the app.

## Start here

For any Role Prep request, use the **`roleprep-lead`** agent. It plans the work,
routes each part to a specialist and runs the gates. Or use a command:

| Command | Does |
|---|---|
| `/new-subtopic <topic> <title>` | Plan, write, review and gate a new sub-topic |
| `/review <file>` | Blind quality review (PASS or fix list) |
| `/refresh-topic <topic>` | Find outdated facts in a topic |
| `/pilot-scoring <subtopic>` | Gate 1: does AI scoring agree with a human? |
| `/ux-review <screen> [prototype or review]` | Prototype or review a screen |
| `/build-story <RP-x.y>` | Build an epic story in ajch_platform, test and gate it |
| `/qa <what>` | Test anything and report with evidence |
| `/release [summary]` | Version, changelog and release PR |
| `/doc <name or link>` | Write, update or import a planning doc into `docs/` |

## Model policy: high quality at the lowest cost

Agents declare a **role** in `kit/agents/<name>.md`; the framework maps role →
tier → model and effort, so no agent file names a model. Planning and gates run
on Opus, volume work on Sonnet, mechanical work and every command on Haiku. A
step that fails the same gate twice escalates once to the next tier, and the
lead records it. The full table and rules are in the `model-policy` skill.
Work you type outside a command runs on the session's model, so use
`/model sonnet` day to day and keep Opus for planning.

## The kit is generated

`.claude/` is rendered by [ajch_agent_framework](../ajch_agent_framework) from:

- `kit.json`: vertical, synced files, protected paths, checks per path, docs order
- `kit/agents/`, `kit/skills/`, `kit/commands/`: this vertical's own sources

Edit those, then run `npm run kit`. The guard hook blocks hand edits to generated
files, `.claude/kit.lock.json` records the framework version and a hash per file,
and CI fails on drift (`npm run kit:check`). `.claude/settings.json` and the
synced files are not generated.

## Docs

`docs/` holds the planning docs in reading order: business case, use cases,
epic and stories, UX and UI plan, repo and kit plan. Start at `docs/README.md`.

## Gates that run automatically

- **After every write** under `content/roleprep/`, a hook runs
  `scripts/validate-content.mjs` and `scripts/check-options.mjs`; failures are
  fed back to the agent (exit 2) to fix before it moves on. Writes under
  `docs/` run `scripts/check-docs.mjs` the same way.
- **Before every write**, a hook blocks edits to `content/roleprep/examples/`
  (archived) and to files synced from ajch_platform.
- **CI** (`.github/workflows/validate.yml`) runs both validators, the docs check, the kit drift check and builds the plugin.

## Commands

```bash
npm run kit       # render .claude/ from kit/ + kit.json (never edit .claude/ generated files)
npm run check     # both validators
npm --prefix app run dev     # the app locally (pre-render on build: npm --prefix app run build)
npm run docs      # planning docs: names, headings, links, diagrams
npm run catalog   # refresh topic counts in catalog.json
npm run plugin    # render the kit, then regenerate plugin/ from .claude/
```

## Rules

- Content facts that change (products, limits, prices) come from an opened source, never memory.
- Every level gets its own answer; the validator rejects copies and the reviewer rejects rewordings.
- `.claude/` (except settings and synced files) and `plugin/` are generated. Edit `kit/` or `kit.json` and run `npm run plugin`.
- Ownership: `.claude/agents/appsec-engineer.md` and the four synced skills are
  owned by ajch_platform and refreshed by its sync script.
